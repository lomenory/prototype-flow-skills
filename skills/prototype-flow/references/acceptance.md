# 场景验收与证据

用于首个项目闭环或交接时选择最小充分场景，不要求每次局部修改重跑全部流程。

| 场景 | 观察结果 |
| --- | --- |
| 两种来源含冲突 | 保留各自出处，关键未决项清楚，不编造已确认业务规则 |
| 从既有 PRD 进入 | 不重复发起全量资料整理，按范围拆分并保留稳定身份 |
| 富文本保存和需求定位 | 标题、表格、图片、链接及需求块往返后不丢失，移动标题仍能定位 |
| PRD 被外部修改 | 旧修订保存被拒绝，未保存草稿保留，可比较双方内容 |
| 两模块共享规则改变 | 标记已知受影响需求，Agent 补充隐含影响，Demo 保持业务状态一致 |
| 生成时 PRD 再次修改 | Demo 仍绑定原输入，明确过期情况，不能覆盖较新正文 |
| 截图入口 | 从看板直达相同页面状态，刷新恢复，继续跨模块流程 |
| 完整历史 | 旧 PRD、页面、图片一起可读；比较有具体差异；恢复创建新修订 |
| 飞书部分失败 | 本地仍可用，成功文档不重写，失败项读回后恢复，无重复创建 |
| 工作台只读 | PRD、画布、历史和资料可浏览；无新增、编辑、上传、版本写入入口；HTTP 写请求返回 405，项目文件不变 |
| 需求复制 | PRD 与画布详情复制准确的名称和编号；剪贴板失败明确提示且可手动复制 |
| 确认关闭待分析 | 当前及旧确认记录只关闭覆盖且未改变的需求；确认后新变更、依赖影响仍显示待分析 |
| 只读检查外部变化 | state/document/compare/validate 和 HTTP GET 前后文件字节及修改时间不变；refresh 才持久化 |
| 无依赖模块修改 | 局部 Demo 保持有效；显式共享规则或传递依赖变化仍使其过期 |
| 截图替换或入口改变 | 旧验证失效；流程步骤中的缺失引用能被保存校验和 validate 发现 |
| 连续小幅修改 Demo | 同一工作稿编号与目录持续保存修订，不每轮增加完整冻结版本；任务输入和恢复依据保留 |
| 工作稿证据与恢复 | 受影响截图失效，未变化证据需有适用依据；恢复旧修订产生新修订，不覆盖原记录 |
| 评审冻结与交付下载 | 冻结产物保持当时内容和真实状态；下载使用当前已保存修订对应的冻结版 |
| 当前 Demo 损坏后恢复 | 完好历史可恢复，恢复前备份保留损坏文件及说明，历史不变 |
| 中断任务历史续作 | 固定输入及部分输出进入快照；新任务恢复这些内容，不覆盖实时任务 |
| 图片成功后正文失败 | 同一飞书计划继续剩余正文，已成功图片不重复上传，固定输入不变 |

使用者可以运行 `python3 -B <skill-dir>/scripts/flow.py validate <project-dir>` 检查项目结构，并按上表验证需要的操作。公开分发包不包含开发测试；维护者仅在开发仓库根运行 `python3 -B -m unittest discover -s tests -v`。技能 frontmatter 可用 skill-creator 的 `quick_validate.py` 检查。结构检查只证明对应结构约束；浏览器实际操作需保留截图或操作证据，云端行为必须注明模拟或真实。

验证新 Skill 的决策时可用隔离项目做独立场景演练：给出原始资料、一个有冲突的既有 PRD 和局部请求，让 Agent 只处理本次范围；观察其是否保留出处、复用已有 Skill、选择正确阶段并遵守真实证据边界。演练不触及真实飞书写入、全局安装或无关项目。
