# 任务与设计依据

## 从任务决定布局

先从已有需求、相邻页面和真实使用路径明确谁在何时打开这页、要完成什么、看到什么才知道完成。找出当前状态最需要的信息、下一步操作及其必要条件。只有缺口会改变行为、信息顺序或保真目标时才询问。现有方案里已确定的用户、状态和术语可以直接复用。

把内容按用户做决定的顺序排列。需要比较的条目对齐同一组字段；按先后完成的任务沿顺序展开；能独立浏览或打开的对象适合用卡片。详情说明放到相关选择旁，字段错误留在可修正的位置。以审批列表为例，先让审批人能找到待处理的申请、辨认状态并进入处理；欢迎语、部门和日期的视觉权重取决于它们对这个动作的作用。

根据内容量、使用频率和设备决定密度、视觉变化与动效。说明这些选择会改变哪个区域的宽度、间距、分组或反馈。只呈现流程确实会出现的状态；查询失败保留仍有效的结果，提交失败保留输入，破坏性操作保留必要确认和恢复信息。

## 确定设计来源

1. 用户明确指定的风格、目标截图、URL、Figma 节点、设计稿或设计系统优先。保真任务记录影响还原的差异。
2. 在既有产品中，先看主题或设计索引、能复用的组件和最相近的一页，再结合适用的品牌规范、组件库和参考产品。决定沿用哪些导航、文本角色、状态、间距和容器。只有实质冲突才补问，局部修改直接继承既有设计。
3. 全新设计或获准整体改版，且没有指定风格或可继承的设计时，从 [UINice](https://uinice.com/search) 按任务、密度和设备寻找母版。查看条目指向的原站与真实预览，选取适用的布局和视觉语言，把内容、状态与交互换成本项目的。实际复用代码、字体或图像时查看原站许可。
4. 目录不可访问或没有合适模板时，按场景、密度和气质从[八套内置设计系统](../../design-systems/index.json)选择一个，仅打开选中的 `DESIGN.md`。索引中的 `path` 从技能根目录解析。将其中的文字、颜色、间距等角色映射到目标项目的语义样式、单位和实际组件。Web 示例中的实现值用于参考。

需要追溯时在现有设计记录中留下实际采用的来源、选择理由及影响外观的推断。只查看过目录缩略图时，不能据此声称已核对原稿。
