# Web 页面

从现有路由、页面壳、主题、表单和列表组件入手。按项目支持的视口与输入方式布局。先保证比较、阅读和操作顺序；在已有断点兼顾换列、折叠和操作可达性。整页所需的纵向滚动可以保留。营销页的首屏应辨认得出内容、主要动作和真实产品；标签、统计、信任标识和装饰只在有相应内容时使用。

## 首屏、列表与素材

首屏直接呈现产品内容。工作台或列表把任务对象、筛选条件及处理入口相邻放置；落地页让访客能看到主张、支持内容和对应动作。按实际内容决定是否使用 Hero、信任信息或图文区。只有分类、状态、来源等能补足标题含义时才增加短标签。长标题先调文字与可用宽度，长文行宽可从约 65ch 起调。图文交错时让说明靠近对应图片，列表保留一致的字段顺序与分隔方式，各网格单元都有内容依据。

真实产品用已有产品图、界面截图和品牌资源；概念占位明确标示来源状态。用一套图标语言。标签底色、强调色、渐变或纹理要能表达状态、分组或产品特征；根据设计依据决定明暗表面，避免按区块任意切换主题、给卡片层层加外框。装饰性版本号、滚动提示、天气或虚构客户标志会分散主任务的注意力。

## 文字与颜色

优先复用项目文本角色。缺少既有规范时，正文可从 15–16 CSS px、行高约 1.5–1.7 起，表单标签、必要帮助、反馈、表头和图表标注可从 14 CSS px 起；12 CSS px 仅用于少量非关键元数据。检查实际渲染值、控件高度、长文字换行与图表缩放。正文与支持文字在实际背景上保持可读，常规文本可按 4.5:1 检查，适用的例外按文本与控件角色判断。透明、渐变或图片背景需要查看实际组合。[文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

现有语义色不足时，可用 Radix 的 1–2 阶作背景、3–5 阶作交互表面、6–8 阶作边框、9–10 阶作实色强调、11–12 阶作文字，并检查实际组合。中性轻分隔可尝试 0.5 CSS px 并看实际显示；焦点、错误、选中、图标及图表线条按辨识度决定。无现成动效时，250 ms 与 ease-out 可作短转场的起点，按用途调整。[Radix 色阶用途](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale) · [非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

## 操作和渲染

使用可见字段标签，Placeholder 用于输入示例。按钮用词对应实际结果，同一操作在不同位置表达一致；确认、取消、禁用和错误在实际背景上可辨。优先使用带有标签与键盘语义的原生控件或项目组件。键盘能到达主要操作，焦点可见，关闭对话框后上下文可恢复。把校验和重试放在受影响位置，重要值在不悬停时也能取得。检查有含义图像的替代文字、实际支持的主题和减少动态效果设置。悬停或按下时避免布局跳动。高频 Web 动画优先 transform 和 opacity，限定需要过渡的属性。窄屏的列数和断点继承项目布局，检查多列折叠、真实触控区域以及固定高度与浏览器可视区的关系。网站代码用项目入口验证真实交互；Web 画板检查约定尺寸的布局与状态，开发验证时再核对键盘和运行时行为。
