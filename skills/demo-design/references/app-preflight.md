# App Flow Preflight

只在 `app_flow` 的 Tier 3 读取。它补充平台化视觉与交互检查，不扩展到第二平台、第二设备或生产级原生实现。

## Design Read

生成前先写清：

- 目标平台、设备框、方向与展示尺寸；未经明确要求不增加第二目标。
- `variance`、`density`、`motion` 三个视觉调节值及其对布局、留白、组件状态和转场的实际影响。
- 一条主要任务路径的起始状态、完成结果，以及适用的错误、取消和恢复路径。
- 主要视觉锚点：内容首屏、主要动作、关键状态反馈和平台导航区。

## Frame and Layout

- 内容不得遮挡状态栏、Dynamic Island/刘海、Home Indicator、系统导航栏或设备框。
- 顶部栏、底部导航、浮层与可滚动内容之间必须有清楚的层级和安全间距。
- 键盘、Sheet、Dialog、Toast、Loading Overlay 出现时，当前任务与主要动作仍可理解；不能把关键内容永久推离可操作区域。
- 长文案、错误文案和动态数据不得在目标尺寸发生裁切、不可恢复的重叠或只显示省略号而失去关键含义。
- 44 CSS px 目标尺寸是硬门禁，不代表可以用过度稀疏或过密的组件堆叠替代清晰节奏。

## Interaction Completion

- 验证声明的任务从起始状态走到成功结果，不以固定点击次数代替任务完成。
- 每一步都要有即时反馈、pending 状态或明确的下一步可用性。
- Back/Close/Escape 必须遵守当前层级：先关闭临时层，再离开当前页面；关闭后焦点或操作上下文可恢复。
- 异步流程提供适用的取消、重试和恢复；破坏性操作提供确认与可观察结果。
- 页面刷新、`window.__DEMO_RESET__` 和 Demo 内持久化边界必须与交付说明一致。
- 所有看起来可交互的控件必须可工作、明确 disabled，或清楚标为 Demo 范围外；不得保留死控件。

## Keyboard and Scroll

- 表单控件具有可见标签、正确输入类型和可理解校验反馈。
- 键盘弹出后检查焦点字段、错误提示和主要提交动作，不允许被遮挡且无法滚动恢复。
- 长页面、列表、Sheet 与嵌套滚动只保留必要滚动轴；滚动到边界后仍能找到返回、关闭或完成动作。
- 如果 App Demo 支持外接键盘路径，验证 Tab、Shift+Tab、Enter、Space 与 Escape；不支持时不得声明已通过键盘验收。

## Rendered Quality Loop

1. 截取初始状态、关键操作后状态、成功状态，以及适用的错误/恢复状态。
2. 对照视觉锚点检查层级、构图、排版节奏、组件一致性、内容真实性和状态可辨识度。
3. 阻塞或重要问题集中修正一次；只重跑受影响路径和截图。
4. Contextual/Advisory 判断写入设计决策或交付说明，不写成机器 `passed`。

阻塞问题包括任务无法完成、关键内容不可读、平台 Chrome 遮挡、主要动作不可达、状态结果不可辨认。重要问题包括明显层级错误、密度失衡、组件状态不一致、键盘或浮层破坏布局。
